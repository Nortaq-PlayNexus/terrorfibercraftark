    Terror Fibercraft 1000x — Usage Guide (v3.1)¶

    The toolkit is a proper, installable Python package under src/terrorfibercraft/, managed natively with uv. This page is the canonical reference for installing and running every tool.

    Install¶

    Requires Python 3.11+ and uv (recommended) or plain pip.

    uv sync --extra bot   # installs the package + dev groups + Discord extra
# to also pre-build docs tooling:  uv sync --all-groups --extra bot

    uv sync creates a .venv, installs the package, and installs the dev dependency group (which itself pulls in the lint, test, and docs groups) from the committed uv.lock. The bot extra adds discord.py, needed only if you run the Discord bot. Activate the venv, or prefix commands with uv run.

    The full set of dependency groups:

    Group Contents
    lint ruff, mypy
    test pytest, pytest-asyncio, pytest-cov, tox, tox-uv
    docs mkdocs, mkdocs-material, mkdocstrings[python], mkdocs-autorefs
    dev pre-commit, build, twine + includes lint/test/docs

    Or, with plain pip:

    pip install -e ".[bot]"        # runtime + Discord
pip install -e ".[bot]" --config-settings=...  # extras not grouped here

    Environment / secrets¶

    Never commit real tokens. Two supported sources:

    1. config.json (for the Discord bot only) — copy config.example.json → config.json.
    2. Environment variables — copy .env.example → .env, or set real env vars.
    Var Purpose
    TF_DISCORD_TOKEN Discord bot token
    TF_NITRADO_TOKEN Nitrado REST API token
    TF_ADMIN_ROLE Required Discord role for admin commands (default Admin)
    TF_LOG_LEVEL Logging level (default INFO)

    Console scripts¶

    All tools ship as console scripts (installed into .venv/bin or Scripts).

    Script What it does
    tf-generator Build / convert / batch / apply cheat spawnactor sculpt batches
    tf-ark-rcon RCON protocol selftest & diagnostics
    tf-nitrado List Nitrado services / test the REST API
    tf-discord-bot Run the Discord admin bot

    Each is also runnable as a module, e.g. python -m terrorfibercraft.scripts.generator_cli ....

    Sculpt generator¶

    tf-generator gen --preset dino_gate
tf-generator gen --mode box --cols 9 --rows 6 --depth 9 --hole behemoth --floor --ceiling --blueprint watervein --json
tf-generator convert --map ragnarok --lat 30.2 --lon 32.8
tf-generator batch --file spots.json > walls.txt
tf-generator list
tf-generator apply --host 1.2.3.4 --port 27020 --password SECRET --file walls.txt

    RCON selftest¶

    tf-ark-rcon --selftest

    Nitrado¶

    TF_NITRADO_TOKEN=xxxx tf-nitrado

    Discord bot¶

    cp config.example.json config.json   # then fill in tokens
tf-discord-bot --config config.json

    The bot registers slash commands via the AdminCog (scripts/cog.py): /status, /players, /donate, /restart. Admin-only commands require the role named by admin_role.

    Lint, type-check, test, build¶

    Via uv directly:

    uv run ruff check src tests
uv run ruff format --check src tests
uv run mypy src
uv run pytest
uv build

    Or via the tox matrix (lint, docs, build, and py311/py312/py313):

    uv run tox -e lint        # ruff + format-check + mypy
uv run tox -e py312       # pytest on Python 3.12
uv run tox -e docs        # mkdocs build --strict
uv run tox -e build       # uv build + twine check
uv run tox                # whole matrix

    pre-commit is configured (.pre-commit-config.yaml):

    uv run pre-commit install

    Docs¶

    The API reference is generated from docstrings with MkDocs + mkdocstrings:

    uv run mkdocs serve       # live preview at http://127.0.0.1:8000
uv run mkdocs build --strict

    Source lives in docs/; the generated site is written to site/ (gitignored).

    Docker¶

    A Dockerfile runs the Discord bot in a container. Mount your config.json (or set TF_* env vars) and run:

    docker build -t terrorfibercraft .
docker run --rm -v "$(pwd)/config.json:/app/config.json" terrorfibercraft

    CI¶

    .github/workflows/ci.yml lints, formats, type-checks, and tests on Python 3.11–3.13, builds sdist + wheel, validates them with twine, and publishes to PyPI (trusted OIDC) on v* tags. A Dockerfile job builds/pushes a ghcr.io image on main. .github/dependabot.yml keeps pip (grouped) and GitHub Actions + docker base images updated.
